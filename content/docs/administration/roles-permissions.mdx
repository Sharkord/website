A user's permissions are the union of their roles. There is no deny at server level.

- **Owner** has everything and bypasses every check, private channels included. It cannot be edited or deleted.
- **Member** is the default role for new users. Any role can be made the default. Deleting a role moves its users to the default role.

## Permissions Worth Knowing

Most permissions do what their name says. These do not:

| Permission | Note |
| --- | --- |
| Manage storage | Separate from Manage server settings. One does not include the other. |
| Manage plugin permissions | Lets the holder grant any plugin capability to themselves. |
| Manage messages | Includes messages posted by plugins. |
| View user sensitive data | Shows identity, IP address and login location. |
| Manage updates | Can trigger a server self update. |

## Channel Permissions

Per channel, for a role or a single user: **View channel**, **Send messages**, **Join channel**, **Speak**, **Share screen**, **Enable webcam**.

They resolve in this order:

1. **Public channels allow everything.** Overrides on them do nothing. Make a channel private to restrict it.
2. **Owner always passes.**
3. **No View channel means nothing else applies.**
4. **A user entry wins**, allow or deny. This is the only way to deny.
5. **Any role allowing it wins.**
6. **Otherwise denied.** Private channels start closed.

## Voice

- Joining needs the server **Join voice channels** plus the channel **Join channel**.
- Webcam and screen sharing need **both** the server and the channel permission. Removing **Share screen** from a role blocks it everywhere, public channels included.
- Losing a permission mid-call stops that stream, it does not disconnect.
- **Move members** only moves people into channels they are allowed to join.

## Storage Quotas per Role

A role can override the per-user storage quota. With several overrides the largest wins, and `0` means unlimited. See [Storage](./storage).
