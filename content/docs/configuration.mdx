`config.ini` lives in the [data directory](/docs/data-dir). It covers the process: ports, limits, proxies. Everything else is in the server settings UI. Restart after editing.

<Alert type="info" title="Rewritten on every start">
  Sharkord merges the file with its defaults and writes it back, so new options
  show up after updates. Comments and unknown keys are dropped. A file that
  fails validation is replaced with the defaults.
</Alert>

```ini
[server]
host=
port=4991
debug=false
autoupdate=false
backupDatabase=true
maxRequestBodyBytes=262144
rateLimitersEnabled=true
allowedOrigins[]=*
trustedProxies[]=127.0.0.1
trustedProxies[]=::1
trustedProxies[]=10.0.0.0/8
trustedProxies[]=172.16.0.0/12
trustedProxies[]=192.168.0.0/16
trustedProxies[]=fc00::/7

[oidc]
enabled=false
issuer=
clientId=
clientSecret=
redirectUri=
disableLocalLogin=false

[webRtc]
port=40000
announcedAddress=
maxBitrate=30000000
```

Lists repeat the key with `[]`, one line per entry.

## Server

| Field                 | Default  | Description                                                                                          |
| --------------------- | -------- | ---------------------------------------------------------------------------------------------------- |
| `host`                | empty    | Address to listen on. Empty means all interfaces. Leave it empty in Docker. |
| `port`                | `4991`   | Port for HTTP and WebSocket traffic.                                                                 |
| `debug`               | `false`  | Verbose debug logging.                                                                               |
| `autoupdate`          | `false`  | Check for new releases every hour and install them. Ignored in Docker. See [Updating](/docs/updating). |
| `backupDatabase`      | `true`   | Snapshot the database before applying migrations. See [Database Migrations](/docs/migrations). |
| `maxRequestBodyBytes` | `262144` | Max HTTP request body, in bytes. Uploads are not affected. |
| `rateLimitersEnabled` | `true`   | Turns every rate limit on or off. The limits themselves are set in the server settings, see [Rate Limits](#rate-limits). |
| `allowedOrigins`      | `*`      | Origins allowed to call the server from a browser. `*` allows any.                                    |
| `trustedProxies`      | loopback and private ranges | Addresses or CIDR ranges whose forwarded headers are believed. See [Behind a Proxy](/docs/https/behind-a-proxy). |

## Single Sign-On

The `[oidc]` section. See [Single Sign-On](/docs/oidc).

## WebRTC

| Field              | Default    | Description                                                                                            |
| ------------------ | ---------- | ------------------------------------------------------------------------------------------------------ |
| `port`             | `40000`    | Media port, UDP and TCP. Open both. |
| `announcedAddress` | empty      | Public IP or domain clients send media to. Set it behind NAT or Docker. |
| `maxBitrate`       | `30000000` | Maximum bitrate per connection, in bits per second.                                                     |

When `announcedAddress` is empty, the server looks up its public IP at startup (icanhazip, ipify or ifconfig.me). Setting it skips the lookup.

## Rate Limits

Rate limits are set in **Server Settings → Rate Limits**, by anyone with the Manage Settings permission. Changes apply without a restart.

Every action has the global limit, 120 requests per minute by default, counted separately per action: per user when logged in, per IP before that. A few actions have their own limit, either because a low one protects a secret (login, server password, owner token) or because normal use needs more room (typing, push to talk, voice streams).

The same tab has a switch to turn every limit off. `rateLimitersEnabled=false` here (or `SHARKORD_RATE_LIMITERS_ENABLED=false`) turns them off regardless of that switch, which is the way back in if a limit set too low locks you out. The tab then shows the limits as disabled.

## Environment Variables

Env variables win over `config.ini`. Empty values are ignored.

| Variable                            | Overrides                   |
| ----------------------------------- | --------------------------- |
| `SHARKORD_HOST`                     | `server.host`               |
| `SHARKORD_PORT`                     | `server.port`               |
| `SHARKORD_DEBUG`                    | `server.debug`              |
| `SHARKORD_AUTOUPDATE`               | `server.autoupdate`         |
| `SHARKORD_BACKUP_DATABASE`          | `server.backupDatabase`     |
| `SHARKORD_MAX_REQUEST_BODY_BYTES`   | `server.maxRequestBodyBytes` |
| `SHARKORD_RATE_LIMITERS_ENABLED`    | `server.rateLimitersEnabled` |
| `SHARKORD_ALLOWED_ORIGINS`          | `server.allowedOrigins`     |
| `SHARKORD_TRUSTED_PROXIES`          | `server.trustedProxies`     |
| `SHARKORD_OIDC_ENABLED`             | `oidc.enabled`              |
| `SHARKORD_OIDC_ISSUER`              | `oidc.issuer`               |
| `SHARKORD_OIDC_CLIENT_ID`           | `oidc.clientId`             |
| `SHARKORD_OIDC_CLIENT_SECRET`       | `oidc.clientSecret`         |
| `SHARKORD_OIDC_REDIRECT_URI`        | `oidc.redirectUri`          |
| `SHARKORD_OIDC_DISABLE_LOCAL_LOGIN` | `oidc.disableLocalLogin`    |
| `SHARKORD_WEBRTC_PORT`              | `webRtc.port`               |
| `SHARKORD_WEBRTC_ANNOUNCED_ADDRESS` | `webRtc.announcedAddress`   |
| `SHARKORD_WEBRTC_MAX_BITRATE`       | `webRtc.maxBitrate`         |

Lists are comma separated: `SHARKORD_TRUSTED_PROXIES="127.0.0.1,::1"`.

`SHARKORD_DATA_PATH` moves the whole [data directory](/docs/data-dir).
