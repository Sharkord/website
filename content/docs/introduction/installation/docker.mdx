---
title: Docker
description: Run the Sharkord image on its own.
icon: Container
---

```bash
docker run -d \
  -p 4991:4991/tcp \
  -p 40000:40000/tcp \
  -p 40000:40000/udp \
  -v ./data:/home/bun/.config/sharkord \
  --restart unless-stopped \
  --name sharkord \
  sharkord/sharkord:latest

docker logs sharkord   # to read the access token on first run
```

Images exist for `linux/amd64` and `linux/arm64`.

| Port | Carries |
| --- | --- |
| `4991/tcp` | HTTP and WebSocket. Put your reverse proxy in front of this one. |
| `40000/tcp+udp` | Voice, webcam and screen sharing. Publish both protocols. |

- **Data.** Everything is in `/home/bun/.config/sharkord`. Mount it or lose it with the container.
- **Config.** Every [`config.ini`](/docs/configuration) option has an env variable. Behind NAT, set `SHARKORD_WEBRTC_ANNOUNCED_ADDRESS`.
- **File ownership.** The container runs as `bun`. Set `PUID` and `PGID` to match the owner of the mounted folder. With `--user` or rootless Podman they are ignored and the folder must already be writable.
- **Health check.** `GET /healthz` returns `{"status":"ok"}`, no auth.
- **Updating.** `docker pull`, remove the container, run it again. The in-app updater is off in Docker.
