Plugins can render React components into fixed slots of the interface. They run in every connected user's browser, on the app's own origin.

### Slots

| Slot             | Where it renders                                                                 |
| ---------------- | -------------------------------------------------------------------------------- |
| `CONNECT_SCREEN` | Below the logo and server name on the connect screen                             |
| `HOME_SCREEN`    | The screen a user lands on after connecting                                      |
| `CHAT_ACTIONS`   | The chat input area, next to the existing buttons                                |
| `TOPBAR_RIGHT`   | The right side of the top bar                                                    |
| `FULL_SCREEN`    | A full-screen view, with a button added to the left sidebar to open it           |

A plugin can fill several slots, and each slot takes a list of components.

### Export a Slot Map

```tsx
// src/client/index.ts
import {
  PluginSlot,
  type TPluginComponentsMapBySlotId,
} from "@sharkord/plugin-sdk";
import { Home } from "./components/home";
import { FullScreen } from "./components/full-screen";

const components: TPluginComponentsMapBySlotId = {
  [PluginSlot.HOME_SCREEN]: [Home],
  [PluginSlot.FULL_SCREEN]: [FullScreen],
};

export { components };
```

### Turn the UI On

Exporting components is not enough. The server decides which plugins contribute UI, so call `ctx.ui.enable()` in `onLoad`:

```ts
// src/server/index.ts
const onLoad = async (ctx: PluginContext) => {
  ctx.ui.enable();
};
```

`ctx.ui.disable()` takes it away again; clients are told either way and update without a reload.

### Writing the Components

Build with [`@sharkord/ui`](https://github.com/Sharkord/sharkord/tree/development/packages/ui) primitives first. React and the app's selector helpers come from the host through globals, so your bundle stays small and there is exactly one React on the page.

Keep the styling simple. Your component renders inside the host's layout, and not every Tailwind utility is guaranteed to exist in the app's build.

For data, read the store with `useStoreSelector`; for anything privileged, call a server [action](./actions). See [Client SDK](./client-sdk).

<Alert type="attention" title="Your client bundle is public">
  `client/index.js` is served unauthenticated to any browser that asks. Never
  put secrets in it, and never rely on client-side checks for authorization.
</Alert>
