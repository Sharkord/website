### 1. Scaffold It

```bash
bun create github.com/Sharkord/plugin-example my-plugin
```

That gives you a working plugin: a command, an action, a setting, an event listener, and two UI components.

```
my-plugin/
  manifest.json
  build.ts
  src/
    server/index.ts     # runs on the server
    client/index.ts     # runs in the browser
    client/store/       # helpers for reading sharkord state
    client/components/  # your React components
    contracts/          # shared types for commands and actions
```

### 2. Link the SDK

The SDK is not published to npm yet, so link it from the Sharkord repository:

```bash
git clone https://github.com/Sharkord/sharkord.git
cd sharkord
bun install

cd packages/plugin-sdk && bun link
cd ../ui && bun link
```

The build tooling is a separate repository:

```bash
git clone https://github.com/Sharkord/plugin-builder.git
cd plugin-builder
bun install
bun link
```

Then, in your plugin:

```bash
cd my-plugin
bun install
bun link @sharkord/plugin-sdk
bun link @sharkord/ui
bun link @sharkord/plugin-builder
```

### 3. Fill In the Manifest

```json
{
  "id": "my-plugin",
  "name": "My Plugin",
  "author": "Me",
  "description": "Does something useful.",
  "homepage": "https://example.com",
  "logo": "https://placehold.co/100x100/white/black",
  "sdkVersion": 1,
  "version": "0.0.1"
}
```

- `id`: lowercase letters, numbers, and dashes only. It **must** match the folder the plugin is installed into.
- `sdkVersion`: the SDK version the plugin targets. It must equal the server's, or the plugin refuses to load.
- `version`: semver, `1.2.3` or `1.2.3-beta.1`.
- `homepage` and `logo` are optional; both must be `http` or `https` URLs when present.

### 4. Write the Server Half

Edit `src/server/index.ts`. Both `onLoad` and `onUnload` are required exports:

```ts
import {
  createRegisterAction,
  createRegisterCommand,
  type PluginContext,
  type UnloadPluginContext,
} from "@sharkord/plugin-sdk";
import type { Actions } from "../contracts/actions";
import type { Commands } from "../contracts/commands";

const onLoad = async (ctx: PluginContext) => {
  ctx.logger.log("my-plugin loaded");

  const registerCommand = createRegisterCommand<Commands>(ctx);
  const registerAction = createRegisterAction<Actions>(ctx);

  registerCommand("hello", { description: "Says hello" }, async (invoker) => {
    return `Hello, user ${invoker.userId}`;
  });

  registerAction("sum", async (_invoker, payload) => payload.a + payload.b);
};

const onUnload = async (ctx: UnloadPluginContext) => {
  ctx.logger.log("my-plugin unloaded");
};

export { onLoad, onUnload };
```

The contracts in `src/contracts/` are plain types shared by both halves; they are what makes `registerCommand`, `registerAction`, and `callAction` type safe.

`ctx.path` is your plugin's folder on disk. Use it for anything you need to read or write, and keep it inside that folder.

Start with one command or one action. Once it loads cleanly, add settings, UI, or voice.

### 5. Build

```bash
bun run build
```

The bundle lands in `dist/<plugin-id>/`, with `manifest.json`, `server/index.js`, and `client/index.js` inside.

`build.ts` also ships a `copyPluginToSharkord` helper with the call commented out. Uncomment it and your build copies straight into `~/.config/sharkord/plugins`, which makes the edit-build-reload loop much shorter.

### 6. Install It

See [Installation](./installation). In short: put the built folder in `plugins/`, enable plugins in the server settings, then enable your plugin.
