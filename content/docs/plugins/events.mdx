`ctx.events.on(...)` subscribes to server events. Use it for automation, logging, and anything that should happen without a user asking.

```ts
import type { PluginContext } from "@sharkord/plugin-sdk";

const onLoad = (ctx: PluginContext) => {
  ctx.events.on("message:created", async (payload) => {
    ctx.logger.debug("message created", payload.messageId, payload.channelId);
  });
};
```

`on` returns an unsubscribe function, and `ctx.events.off(event, handler)` does the same if you kept the handler around. Neither is needed for cleanup on unload: every subscription is removed when the plugin unloads.

### Available Events

#### Users

| Event               | Payload                        |
| ------------------- | ------------------------------ |
| `user:joined`       | `{ userId, username }`         |
| `user:left`         | `{ userId, username }`         |
| `user:joined_voice` | `{ userId, channelId }`        |
| `user:left_voice`   | `{ userId, channelId }`        |

#### Messages

| Event             | Payload                                                                |
| ----------------- | ---------------------------------------------------------------------- |
| `message:created` | `{ messageId, channelId, userId, pluginId, content, textContent }`     |
| `message:updated` | `{ messageId, channelId, userId, editedBy, pluginId, content, textContent }` |
| `message:deleted` | `{ messageId, channelId }`                                             |

`content` is the rich message body; `textContent` is the plain text version. `userId` and `pluginId` are `null` when the message came from the other kind of author, so a message sent by a plugin has a `pluginId` and no `userId`. On `message:updated`, `editedBy` is the user who made the edit, which is not always the author.

Messages your own plugin sends also raise these events. Check `pluginId` before reacting, or you can build yourself a loop.

#### Voice

| Event                       | Payload         |
| --------------------------- | --------------- |
| `voice:runtime_initialized` | `{ channelId }` |
| `voice:runtime_closed`      | `{ channelId }` |

A voice channel's runtime is created when the first user joins and closed when the last one leaves. These are the events to wait for before touching the [Voice](./voice) API: there is no router to get before the runtime exists.

#### Settings

| Event         | Payload           |
| ------------- | ----------------- |
| `setting:set` | `{ key, value }`  |

Raised whenever a plugin setting is written, by an admin in the interface or by a plugin calling `set`. It fires for every plugin's settings, so check the `key`. See [Settings](./settings).

### Handler Rules

- Handlers time out after 10 seconds. Kick off longer work and return.
- A handler that throws or times out is logged to the server log; the other handlers still run.
- Handlers run for events triggered by anyone, including other plugins.
