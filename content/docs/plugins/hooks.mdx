`ctx.hooks.onBeforeFileSave(...)` runs just before Sharkord moves an uploaded file into permanent storage. Use it to scan uploads, or to replace the file with one you produced.

### Signature

```ts
ctx.hooks.onBeforeFileSave(async ({ tempFile, userId, type }) => {
  // return nothing, or the path to a replacement file
});
```

The payload is:

| Field      | Type           | Description                                                        |
| ---------- | -------------- | ------------------------------------------------------------------ |
| `tempFile` | `TTempFile`    | `{ id, originalName, size, md5, path, extension, userId }`         |
| `userId`   | `number`       | Who is uploading                                                   |
| `type`     | `FileSaveType` | What the file is for                                               |

`tempFile` is frozen. Mutating it does nothing; to change the file, write a new one and return its path.

### File Types

`FileSaveType` is exported by the SDK:

- `MESSAGE`
- `AVATAR`
- `BANNER`
- `EMOJI`
- `SERVER_LOGO`

### Returning a Replacement

Return **nothing** to let the upload continue untouched, or an **absolute path to a file that exists on disk** to swap it in. Sharkord then re-reads the size and checksum from your file and deletes the original temp file.

```ts
import { FileSaveType, type PluginContext } from "@sharkord/plugin-sdk";
import path from "path";

const onLoad = (ctx: PluginContext) => {
  ctx.hooks.onBeforeFileSave(async ({ tempFile, type, userId }) => {
    if (type !== FileSaveType.AVATAR) return;

    const outputPath = path.join(ctx.path, `avatar-${tempFile.id}.webp`);

    await convertToWebp(tempFile.path, outputPath); // your code

    ctx.logger.debug("replaced avatar upload", tempFile.originalName, userId);

    return outputPath;
  });
};
```

Returning a path that does not exist aborts the upload with an error. Return nothing if your processing failed and you want the original to go through.

### Notes

- Every registered hook runs, in registration order, and each one sees the result of the previous.
- This runs inside the upload request, so a slow hook is a slow upload for the user. Keep it quick, and do heavy processing after the fact.
- Sharkord decides the final stored name itself. You control the file, not where it lands.
- The hook is unregistered automatically when the plugin unloads.
