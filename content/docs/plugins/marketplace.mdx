The marketplace is the [Sharkord/plugins](https://github.com/Sharkord/plugins) repository, browsable from the server settings and on [sharkord.com/plugins](/plugins). Installs are checked against the published checksum.

<Alert type="attention" title="A listing is not a review">
  Anyone can publish. The `verified` badge means the maintainers know the
  publisher, not that the code was audited. See [Security](./security).
</Alert>

## Registry Layout

```
plugins/<plugin-id>/
  plugin.json             id, name, description, author, logo, homepage,
                          screenshots, tags, categories, verified
  versions/<version>.json version, downloadUrl, checksum, sdkVersion, size, timestamp
```

## Publish

The plugin needs a public GitHub repository. Set `GITHUB_TOKEN` in `.env`, a [personal access token](https://github.com/settings/tokens) with `repo` scope, then:

```bash
bun run publish
```

The scaffold's `publish.ts` passes `repo: "owner/repo"`. Change it to your repository, or remove it to use the `origin` remote.

It then:

1. Builds the plugin.
2. Creates a GitHub release tagged `v<version>` and uploads the `.tar.gz` and the version file.
3. Forks the registry under the token's account and opens a PR adding `versions/<version>.json`, and creating or updating `plugin.json` from your manifest.

Once the PR is merged, every server sees the new version.

- **Bump `version` in `package.json` first.** Publishing fails if the tag or the registry version already exists.
- **Screenshots, tags, categories and `verified` live only in the registry.** Publishing never changes them. Add screenshots and tags by editing `plugin.json` in the PR or in a later one.
- **`pr: false`** in `publish.ts` only creates the release, without the PR.

<Alert type="info" title="sdkVersion pins compatibility">
  Servers only offer versions whose `sdkVersion` matches theirs. Publish a new
  release after every SDK bump, or existing installs cannot update.
</Alert>
