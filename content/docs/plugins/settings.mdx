Register settings and they show up on your plugin's page in the server settings, where an admin can change them without touching code. Values are stored in the database and survive restarts.

### Register

```ts
import type { PluginContext } from "@sharkord/plugin-sdk";

const onLoad = async (ctx: PluginContext) => {
  const settings = await ctx.settings.register([
    {
      key: "welcome-enabled",
      name: "Enable welcome messages",
      description: "Send a message when a user joins the server.",
      type: "boolean",
      defaultValue: true,
    },
    {
      key: "welcome-channel-id",
      name: "Welcome channel",
      type: "number",
      defaultValue: 1,
    },
  ]);

  const enabled = settings.get("welcome-enabled"); // boolean
  settings.set("welcome-enabled", false);
};
```

`register` is async: it reads the stored values, fills in defaults for keys it has not seen, writes them back, and hands you a typed accessor. Call it once, in `onLoad`, and keep the returned object.

A definition takes `key`, `name`, `type`, `defaultValue`, and an optional `description`. Types are `string`, `number`, and `boolean`.

### Reading and Writing

`get` and `set` are **synchronous**. `get` reads the value from memory; `set` updates it and persists in the background, so it does not return a promise and there is nothing to await.

```ts
const channelId = settings.get("welcome-channel-id"); // number
settings.set("welcome-channel-id", 42);
```

`set` on a key you never registered is ignored and logged as an error in the plugin's log.

### Reacting to Changes

An admin editing a value in the interface does not go through your `set`, so watch the [event](./events) instead:

```ts
ctx.events.on("setting:set", ({ key, value }) => {
  if (key !== "welcome-enabled") return;

  ctx.logger.log("welcome messages are now", value);
});
```

The event is global, so filter by `key`, since you will also see other plugins' settings.

### Notes

- Values written from the interface are type-checked against your definition; a `number` setting cannot be set to a string.
- Settings are cleared from memory when the plugin unloads and reloaded from the database on the next `register`. The stored values are not deleted when a plugin is disabled.
- Anything an admin can read in the interface is not a secret from admins. Use them for API keys if you like, but see [Security](./security).
