<Alert type="warning" title="Back up first">
  Sharkord is in alpha and database migrations are not reversible. Copy your
  [data directory](/docs/data-dir) somewhere safe before every update, so you
  can roll back by restoring it alongside the old binary.
</Alert>

### Manual Update (Recommended)

1. Stop the server.
2. Download the [latest release](https://github.com/Sharkord/sharkord/releases/latest) for your platform.
3. Replace the old binary with the new one and start it again.

Your configuration and data are untouched; they live in the data directory, not next to the binary.

### Docker

```bash
docker pull sharkord/sharkord:latest
docker rm -f sharkord
# start the container again with the same command
```

Or with Compose:

```bash
docker compose pull
docker compose up -d
```

### From the Admin Panel

If you have the `MANAGE_UPDATES` permission, the server settings show the current version, the latest release, and a button to update. The server downloads the new binary and restarts itself.

This is unavailable in Docker, where the image is the unit of update, and in development builds.

### Automatic Updates

Set `autoupdate` in [`config.ini`](/docs/configuration):

```ini
[server]
autoupdate=true
```

The server then checks GitHub for a new release at startup and once an hour, and restarts itself when it installs one. It is off by default, and unavailable in Docker.

<Alert type="attention" title="Both automatic paths are unreliable for now">
  Self-updating does not work in every environment, and a failed update can
  leave the server down until you replace the binary by hand. Until this is
  more solid, prefer the manual update or a fresh Docker image.
</Alert>
